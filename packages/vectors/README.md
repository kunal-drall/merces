# Merces parity vectors

Generated by `pnpm vectors` (repository root) from `packages/reference/src/vectors`. **Never edit by hand**:
the files are byte-reproducible (fixed salts, keys and deterministic Groth16 proofs) and CI fails when they
drift from the reference implementation. `schema.json` is the JSON Schema (draft-07) of a vector;
`known_answers.json` holds the SDK encoding known answers (hashes, signed-message pre-images, periods).

Both chain harnesses must replay every vector and match every `expect` to the base unit (brief F1).

## Conventions

- Integers are decimal strings (stablecoin base units with 6 decimals, WAD = 1e18 ratios, unit counts,
  unix seconds, period ids). Hashes, salts and commitments are 0x-prefixed lowercase hex.
- `t` is the block time the harness sets **before** executing the step (never decreases inside a vector).
- Actors are names (`issuer`, `b1`, `attestor1`, …); each harness maps them to fresh keys/wallets. The
  fee collector is one global account. `keeper` is any permissionless caller.
- `keys` lists the secp256k1 **test** keys of attestors and report-verifier keys: `seed`, the derivation
  (`keccak256("MERCES_TEST_KEY" ‖ utf8(seed)) mod (n−1) + 1`), the private key and the 20-byte address.
  Harnesses register the address and sign the SPEC §1.4 messages themselves, because the message domain
  differs per chain. Nothing in a vector is secret.
- `seriesPrivate` exposes the plaintext behind each `termsCommitment` (θ, r, currency, indexing rule,
  salt) so a harness can recompute `Poseidon(5)`; real series never publish this.
- Commitments that depend on wallet bytes (bid/ask commitments, domain) are recomputed by the harness from
  the plaintext fields in the step (`price`, `quantity`, `salt`, the actor's wallet).
- Periods: `period_id = year × 4 + quarter − 1` (2026 Q1 = 8104).
- Income and θ inside the circuit are in the income currency at the stablecoin's decimals; `fxAvgWad` is a
  pure WAD ratio (1e18 for stablecoin income).

### `expect`

Asserts the state after the previous step. Fields present must match exactly: `balances[actor].stable`
(and `.units` of the step's series), `treasury`, `vault`, `feeCollector`, `auctionEscrow`, `routerBalance`,
`windowEscrowStable`, `windowEscrowUnits`, `ledger` (status is the **derived** status at `t`; see
`schema.json` for the field list), `auction` (tally results), `holders[actor]` (`pending`, `redeemedUnits`)
and `fx[pairId]` (accumulator sums and per-quarter averages).

### `expect_revert`

`call` is any action step without `t`; `error` is one of the canonical names below. The call must fail and
leave the state unchanged.

## Proof encodings

`proof`/`publicSignals` are snarkjs JSON. `proofEvm` holds `pA`, `pB` (imaginary part first), `pC`,
`pubSignals`, `proofBytes` (= abi.encode(pA, pB, pC)) and `calldata` for
`verifyProof(uint256[2],uint256[2][2],uint256[2],uint256[6])`. `proofSolana` holds big-endian bytes for
groth16-solana: `proofA` is **already negated** (`x ‖ q − y`), `proofB` = `x.c1 ‖ x.c0 ‖ y.c1 ‖ y.c0`,
`proofC`, `proof` (= A ‖ B ‖ C, 256 bytes) and `publicInputs` (six 32-byte scalars). See
`circuits/README.md`.

## Signed messages

Magic strings: `REPORT` = `"MERCES_REPORT_V1"`, `FX` = `"MERCES_FX_V1"`, `AMEND` = `"MERCES_AMEND_V1"`, `PAUSE` = `"MERCES_PAUSE_V1"`, `EXTINGUISH` = `"MERCES_EXTINGUISH_V1"`, `TRUEUP` = `"MERCES_TRUEUP_V1"`. Byte-exact pre-images and digests for both a Solana and an EVM test domain are in
`known_answers.json` (`messages`), signed with the same test keys.
