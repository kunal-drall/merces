## Conventions

- Every amount is a `u64` in stablecoin base units; prices are base units per unit; periods are
  `u32` ids (`year × 4 + quarter − 1`); timestamps `u64` unix seconds. Anchor's Borsh decoding
  enforces the §1.1 range rule (a `≥ 2^64` argument cannot be encoded).
- Commitments: `keccak256(price_u64_be ‖ quantity_u64_be ‖ salt_32 ‖ wallet_32)`.
- Signatures: 65-byte `(r, s, v)`, `v ∈ {27, 28}`, low-s; messages per SPEC §1.4 with
  `domain = keccak256(0x01 ‖ chain_id_u64_be ‖ registry_program_id)` and `series_key` = the
  `Series` PDA.
- **Remaining accounts.** Instructions that move a Token-2022 stablecoin take the stablecoin's
  transfer-hook accounts as remaining accounts (`[hook_program, extra_account_meta_list, …]`);
  instructions that move units take the Merces hook accounts
  `[merces_hook, extra_account_meta_list(mint), ProtocolConfig, Series, merces_protocol, EscrowArm]`.
  The programs resolve them with `spl_token_2022::onchain::invoke_transfer_checked`, so a superset
  may be passed.
- **ATAs.** Payout destinations are always the owner's associated token account (derivation checked
  on-chain). `deliver_bid` and `process_order` create the recipient's ATAs idempotently (the payer
  funds them) so a missing account never strands a delivery.

## Protocol instructions

Raise (§5):

| Instruction | Signer | Arguments | Remaining accounts |
| --- | --- | --- | --- |
| `prepare_raise` | issuer | | creates Auction, Treasury, Ledger, EscrowArm and the four stablecoin PDAs |
| `open_raise` | issuer | | creates the unit mint (TransferHook, PermanentDelegate, MetadataPointer + metadata), registry `mark_raise_opened`, hook `initialize_extra_account_meta_list`, the two unit escrow ATAs |
| `cancel_raise` | issuer | | Open and no bids |
| `commit_bid` | bidder | `commitment, escrow` | stablecoin hook accounts |
| `reveal_bid` | bidder | `price, quantity, salt` | |
| `begin_settlement` | anyone | `clearing_price, q_above_claim, q_at_claim` | `TallyInProgress` while a round is open |
| `tally_bids` | anyone | | ≤ 24 `Bid` PDAs (writable) |
| `finalize_settlement` | anyone | | never reverts on a wrong proposal (`SettlementRejected`) |
| `process_bid` | anyone | | stablecoin hook accounts; the last call finalises the mint |
| `deliver_bid` | anyone | | unit hook accounts (+ stablecoin hook accounts) |

Treasury (§5.3): `claim_release` (issuer), `set_release_pause(paused)` (issuer),
`request_early_draw(amount)` (issuer + configured approver co-sign).

Repayment (§6): `submit_report(args)` (issuer; `args = {period, payment_usd, fx_avg_wad,
fx_fallback_sig?, fx_attestor_addr, prior_income_commitment, income_commitment, tier, liquidity_event,
proof[256], attestation_sig?, attestation_addr}`; optional accounts `fx_pair`, `fx_start`, `fx_end`,
`router`), `pay` (anyone pays; the `Report` of the open due period), `submit_trueup(year, adjustment,
attestation_ts, attestor_addr, attestor_sig)` (issuer), `pay_trueup`, `crank_status`,
`retire_if_capped`, `request_pause` / `withdraw_pause_request` / `end_pause` (issuer),
`approve_pause(pause_end, attestor_addr, attestor_sig)` (anyone).

Holders (§6.3, §6.7–§6.9): `register_holder(wallet)`, `claim`, `burn_retired`, `claim_redemption`,
`claim_tail`, `claim_final` — all permissionless pushes to the holder's ATAs (`HolderClaim` accounts;
stablecoin hook accounts as remaining accounts).

Router (§6.5): `init_router` (anyone, before settlement; terms from the Series), `route` (anyone;
sweeps the receiving account), `close_router_period(period)`.

Rate accumulator (§6.6): `init_fx_pair(pair_id)`, `snapshot_fx(period)` with a Pyth `PriceUpdateV2`
account (full verification).

Exit (§6.7, §6.9): `redeem` (issuer), `extinguish(attestor_a, sig_a, attestor_b, sig_b)` (anyone).

Window (§7): `open_window(period)`, `commit_ask(commitment, units)` (holder; unit hook accounts),
`window_commit_bid(commitment, escrow)` (allowlisted wallet), `reveal_order(price, quantity, salt)`,
`begin_window_settlement(clearing_price, no_match)`, `tally_orders` (≤ 24 `Order` PDAs),
`finalize_window`, `process_order` (anyone; revealed bids in reveal order, then revealed asks in reveal
order; unrevealed orders and NO_MATCH windows any time).

## Hook instructions

- `initialize_extra_account_meta_list` — mint authority (the protocol's `auction_auth` PDA) signs;
  requires `Series.unit_mint == mint`; writes the 4-entry list `[ProtocolConfig, Series,
  merces_protocol, EscrowArm(external PDA of merces_protocol: ["escrow_arm", mint])]`.
- `execute(amount)` — called by Token-2022 on every transfer; rules of SPEC §4.1.

## Off-chain integration notes

- Settlement keepers: read every `Bid` of the series (program accounts filtered by the `series`
  field), compute `q_above / q_at` for the candidate price and propose with `begin_settlement`;
  tally in pages; `finalize_settlement`; then `process_bid` for every bid (any order) and
  `deliver_bid`.
- Window keepers: the same with `Order` accounts; `process_order` must follow the per-side reveal
  order (`Window.next_bid_index`, `next_ask_index`).
- Reports: `units_outstanding` for the proof is `Ledger.units_outstanding` (or
  `units_at_redemption` after redemption); tier-1 reports need `close_router_period` (or a routed
  receipt) for `period` and `period − 1`.
