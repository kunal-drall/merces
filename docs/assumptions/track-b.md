**Further findings (not §13 items).**

- Liveness: `submit_report` requires the FX start checkpoint as a typed optional account, so a quarter with
  **no snapshot at all** can never be reported, not even with an attestor fallback rate; the end checkpoint
  is optional too, so a caller could hide an existing `p+1` checkpoint → both become address-checked
  accounts read only when initialised (missing start ⇒ `NeedsFallback`).
- Harness: actors without a stablecoin account (vector 03), tier-1 routers never initialised (vector 12),
  `ledger.proceeds` must be the deposited proceeds (`proceeds_received`, vector 18), `raiseState` during the
  reveal phase is `Open` (vector 15).
- Missing deliverables: C11 charter tests (one per rule), charter byte-snapshot test, §1.4 known-answer
  test, fuzz/property tests at program level, `docs/solana/MEASUREMENTS.md`, `docs/solana/AUDIT-NOTES.md`,
  `solana/idls/`, `solana/scripts/deploy*`, `solana/deployments/`, local-validator rehearsal.

| B-C7 | §9 tender, CURVE_MODE §7 | The base mint has no permanent delegate, and units keep circulating after redemption (units bought out of the DAMM v2 pool were not in the census). | `redeem` takes the census as its eight remaining accounts, stores it as `units_at_redemption` and deposits `floor(P_redeem × units / 10^6)`. `tender_units(from_stake, from_wallet)` (registered holder) pays `floor(P_redeem × units / 10^6)` plus pending payouts and **burns the units in place by their owner's authority** (the `curve_stake` PDA for staked units, the holder's signature for wallet units): no permanent delegate and no burn escrow are needed. Staked units at redemption are reserved; wallet tenders share `units_at_redemption − tendered_total − staked_total` (`TenderQuotaExhausted`), so tenders never exceed the deposit (`properties.rs::tenders_never_exceed_the_deposit`). The tail clause weighs tendered units (`Holder.redeemed_units`); `claim_redemption` refuses (`CurveUsesTender`). Events `UnitsBurned(reason 1)` + `RedemptionClaimed`. |
| B-C8 | §9 retirement | "At the cap, claims end and the series retires without forced burns." | Retirement as sealed-bid (vault accumulators, `SeriesRetired`); `burn_retired` refuses (`CurveModeNoBurn`), `claim` never burns (`PayoutClaimed.burned_units = 0`), pending payouts stay claimable, unstaking stays open. |
| B-C9 | CURVE_MODE §2 `mark_curve_complete` | Naming and who writes the registry. | Protocol instruction `complete_curve` (anyone): `quote_reserve ≥ migration_quote_threshold` → registry `mark_raise_result(Settled)` at `finish_curve_timestamp` with the stored `units_sold` / `P0` (the registry refuses other values or states for curve series) and `mark_mint_finalized` (the DBC mint never had a mint authority); repayment and treasury open. `RaiseSettled.proceeds = 0` (proceeds arrive via B-C4). Failed and Cancelled are unreachable; a pool that never completes stays Open. |
| B-C10 | §3.1 / §9 registry | The registry needs the USDC mint to check "stablecoin = USDC" and the creator choice. | `ProtocolConfig.curve_quote_mint` (an `init_protocol` argument; deploy scripts `--curve-quote-mint`, default the mock USDC) and `Series.dbc_creator`. `create_series` in curve mode: `min_raise ≥ 1` (`CurveThresholdZero`), lockup, wallet cap and raise durations 0 (`CurveTermsNotZero`), stablecoin = `curve_quote_mint` (`CurveQuoteMintMismatch`); `MinRaiseTooHigh` and the wallet-cap feasibility check do not apply. This changes the registry layout before its first immutable deployment (the localnet record was regenerated). |
| B-C11 | CURVE_MODE §5 "roll over" | Payouts for units nobody staked. | Their share stays in the vault token account, unclaimable (it counted toward the cap, as the issuer paid it); it is not redistributed to stakers. Open item for Kunal: carrying it into later distributions would need a census-time sweep. |
| B-C12 | PROCEEDS_OPTIONS Q5 | Creator trading fees and creator surplus with the issuer as creator. | Not checked at activation: with `creator_trading_fee_percentage > 0` the issuer claims its trading-fee share and the creator surplus (rounding-level) directly from DBC. They are buyers' fees, not raise proceeds; the default is `c_t = 0`. |
