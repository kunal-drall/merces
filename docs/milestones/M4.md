# M4 — Raise and clockwork

**Built.** E6 auction service: bid pre-checks (allowlist, 10% wallet cap, phase, reserve, duplicate, balance, deposit
with the 1% fee), commit/reveal/refund builders, a commitment helper, client-encrypted reveal backups the server
cannot read (plaintext bid fields are rejected), an offchain clearing preview from revealed bids, keeper settlement
and reveal reminders. E7 keepers: an in-process scheduler with `keeper_runs` logging and idempotent jobs for auction
settlement, reveal reminders, status/pause/burn cranks, report-deadline reminders (due-soon, due, grace end, once
each), FX coverage flagging with attestor fallback requests, transfer windows (built, gated by the `transfer_windows`
flag) and outbox dispatch; a `dev:keepers` entry point. E8 rate keeper: once per UTC day per pair per chain, Pyth
(Hermes-shaped port with runtime feed-id resolution that fails closed), publish-time and confidence checks,
Chainlink cross-check where a feed exists, deviation beyond the band → no snapshot, quarter flagged, attestor request
opened. Price-feed ports with mocks; Hermes adapter named route-for-route. 84 operations in the contract.

**Assumed.** A-FX-2: the live contracts are expected to read Chainlink themselves; the simulator trusts the
keeper's deviation evidence. Chainlink publishes no FX feeds on Monad, so there only the coverage rule applies until
a second source is chosen. The deviation band is a 100 bps placeholder (A-FX-3).

**Open.** Weekend handling of FX feeds (A-FX-1) is a shared question with Stage 1; the deviation band (Part J.8).
