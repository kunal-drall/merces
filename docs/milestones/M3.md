# M3 — ProofOfIncome

**Built.** zkTLS port shaped after Reclaim's JS SDK 5.x (session → proof → verify) with a mock that proves
from synthetic source data, and source definitions in Reclaim's custom-provider shape for Stripe (balance
transactions), Deel (payments) and DistroKid (earnings page, OPRF-hashed), in that build order; a proof-system
port (mock now, snarkjs Groth16 verifier ready for Stage 1's circuit) and served prover artifacts (placeholder);
the shared zk public-input layout in `@merces/domain`. `@merces/report-verifier`: an isolated HTTP service with
no database and no payload logs that verifies the zkTLS proof, recomputes the income commitment, and signs
`{series, period, income_commitment, tier}` (the proof's source is checked but not signed, A-REV-1) with a KMS-held ed25519 key; logs carry request ids,
routes, outcome codes and timings only. `@merces/poi-device`: what runs on the issuer's device (payment,
commitment, proof, attestation request, assembly) so income never reaches the API. E5 service: reporting
schedule with deadlines and next steps, zkTLS sessions, FX basis resolution (unity / accumulator / attestor
fallback), offchain verification of public inputs, proof and attestation against the chain's registered keys,
report storage (commitments, amounts, statuses only), `submitReport` and `payIn` builders with the exact
amount the chain reports, tier-1 split reconciliation, tier-4 behind the (off) flag. 76 operations in the
contract; tests run the full tier-2 cycle on both personalities with Stripe-shaped fixtures and exercise every
rejection path.

**Assumed.** r = s / N with N = units *offered* (C1), so a raise that sells half its units pays half the share
rate on excess income (the harness and seed were corrected to this). The test harness uses a 20% wallet cap so
five synthetic backers can sell out a 500-unit series; the protocol default stays 10%. Tier 1 reports also carry
a verifier attestation when the device can produce one; the chain requires only the proof (A-REP-6).

**Open.** Reclaim developer account and custom providers for Deel and DistroKid (Part J.3); hash-attesting
providers need a commitment scheme agreed with Reclaim before the verifier can stop seeing figures; Stage 1's
circuit and verifying key.
