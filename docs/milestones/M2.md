# M2 — People and paper

**Built.** `@merces/ports` (KMS port with a deterministic local dev signer for ed25519 and secp256k1, AES-256-GCM
vault crypto, wallet signature verification for Solana ed25519 and EVM personal_sign, identity-check and
e-signature ports with mocks). `@merces/services` with three modules over the gateway:
E2 identity (nonce/verify sign-in for both wallet families, one account linking both, applications with
encrypted notes, mock identity checks, R27 readiness report, admin review with audit log, approval that adds
the wallet to the chain allowlist through the allowlist-manager role, revocation that removes it without
stranding value); E3 contracts (placeholder HEU and Charter templates rendered from the draft, e-signature
envelope, signed bundle stored encrypted, its hash anchored in `createSeries`; a raise cannot be created
without it); E4 terms (bounds and defaults validation, threshold floor from the E9 table, private terms
encrypted in the vault, disclosure to eligible backers and the issuer with an access log, client-recomputable
commitments, yearly inflation amendments proposed → attested as favourable → built with the attestor as
co-signer → applied by rotating the vault). A `POST /tx/send` relay for user-signed transactions.
`@merces/server` now composes api + services (dev:mock seeds accounts for every persona). 62 operations in
`openapi.yaml`, all contract-checked; 7 API integration tests cover the flows end to end.

**Assumed.** The threshold floor is checked only when a row exists in the same currency (A-REP-4); a missing
row is a validation issue, not a silent pass. Decision reasons are codes, never free text about a person.

**Open.** Real identity and e-signature providers (Part J.1). Counsel's templates replace the placeholders.
