# M5 — Everything else

**Built** (five modules, each with its migration, OpenAPI fragment and API tests; 154 operations in the contract):

- **E9 threshold** — admin upsert/delete of median-income and inflation rows (source and retrieval date required,
  placeholder flag explicit), append-only `threshold_data_history`, public `GET /thresholds`, yearly indexing
  candidates (series with the `cpi-annual` rule and no amendment for the year) and a once-per-year notify run.
- **E10 attestor** — the attestor queue across both chains; hardship review with end-to-end encrypted evidence the
  server cannot read (plaintext-looking payloads are rejected), `requestPause`/`approvePause` builders, holder view with
  statuses and dates only; tier-3 cases (encrypted documents, a client-side prefill specification, attestor sign-off)
  and the annual true-up (over/underpayment as amounts, 60-day deadline, no accrual); fallback FX rate signing;
  two-attestor extinguishment transactions.
- **E11 accounting** — fee ledger by chain/series/kind, per-series statements (gross vs cap, fees, payouts, refunds,
  treasury, redemption, tail), reconciliation runs comparing indexed totals with the chain (fee collector balances,
  vault totals, treasury), RFC 4180 CSV export; the issuer sees their own statement.
- **E12 notifications** — outbox dispatcher resolving recipients (account, issuer, holders, bidders, admins,
  attestors) into inbox rows deduplicated per (payload hash, account), an email channel port with a mock writing to
  `email_outbox`, per-account preferences (email on/off, muted kinds), status-only templates; admin views of the
  backlog and the mock emails.
- **E13 admin** — overview (chains, indexer cursors, keeper runs, outbox backlog, applications, flags), flags (the
  `private_payouts` flag can never be enabled), audit-log reads, attestor and verifier-key registration as tracked
  multisig transactions confirmed from the chain, pause-new-raises, eligibility sync view, tier-4 audit sampling
  scaffolding (returns nothing while the flag is off), keeper runs.

Integration fixes found while wiring the modules: E5 now persists the tier-3 attestor so `submitReport` carries the
co-signer; the terms service keeps the indexing rule as public metadata; the simulator counts tail payouts in the vault
gross and fee totals (reconciliation would otherwise drift).

**Assumed** (recorded in ASSUMPTIONS.md as A-M5-*): a muted notification kind is skipped entirely; the attestor role was
first granted at proposal time (since replaced by the owner's decision: access starts only once the onchain
registration is indexed, A-M5-2); an admin can read
hardship ciphertext but not decide on an attestor's behalf; any inflation amendment row for a year counts as handled;
`GET /admin/accounting/reconcile` persists a run (side effect on GET, as the brief words it).

**Open.** Dedicated templates for the E10 notification kinds; whether sweeping the fee collector should net out in
reconciliation (a sweep ledger); whether a rejected inflation amendment re-opens the candidate; an inbox-always mute.
