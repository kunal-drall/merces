# M1 — Read side

**Built.** `@merces/db` (pool, SQL migrations, per-test schemas, bigint-safe parsing); `@merces/core`
(privacy-safe logger with key redaction and a capture buffer for the canary, idempotency keys, outbox, a
SKIP LOCKED job queue, append-only audit log with a trigger, feature flags); `@merces/indexer` (E1: one
Postgres read model over both chains, idempotent upserts keyed by (chain, seq), resumable per-chain cursor
advanced in the same transaction as the projections, duplicate/out-of-order/gap handling, `confirmed`
events parked in `events_pending` and only `finalized` ones projected into money tables, a public activity
table that never stores an amount); `@merces/api` (Fastify, session tokens, declarative access tiers per
route, public/holder/issuer read endpoints, `/me` holdings with yield, mock-only `/dev` time travel and
faucet); `openapi.yaml` v0 with `x-access` per operation and a contract check that fails CI when routes and
spec diverge; `@merces/client` (openapi-typescript types plus a thin typed fetch wrapper);
`@merces/scenarios` (seeds the 12-issuer cohort on both personalities from Stripe-shaped fixtures) and
`pnpm dev:mock` (persistent simulators + seed + indexer + API in one process).

**Assumed.** Unit counts and statuses are public; amounts (periods, payouts, treasury, vault) are served only
to holders and the issuer. Issuer ids are `<chain>:<address>` like series ids.

**Open.** Sign-in (E2) issues sessions in M2; until then tests mint session tokens directly. Yield is
realised yield (claimed ÷ cost basis); an annualised figure needs a pricing convention.
